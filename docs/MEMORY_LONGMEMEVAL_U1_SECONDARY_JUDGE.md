## 手順

1. U1 の実行が全件終わった後、`scripts/eval/longmemeval_u1_claude_judge.py sheet` で採点シートを作る。
   - 入力は `prepared.json` と `answers.json` だけ。Qwen の採点（`judges.json`）と U1 の報告書は読まない。
   - 各問の4条件の回答を A〜D に置き換え、問ごとに seed `longmemeval-u1-claude-judge-v1` で順番をばらばらにする。対応表 `key.json` は別ファイルにし、採点者は採点が終わるまで開かない。
   - 各問に、Qwen judge と同じ公式 LongMemEval の種類別の基準文を添える（`longmemeval-g1-judge.json` の各テンプレートの指示部分）。
   - 生成に失敗した回答は採点せず、Qwen の経路と同じく0点にする。
2. 採点者（このセッションの Claude Opus 5.5）が、シートだけを読んで全回答に yes/no を付け、`labels.json` に保存する。**U1 の報告書、`judges.json`、対応表は、この保存が終わるまで開かない。** 採点をやり直したり、保存後にラベルを変えたりしない。
3. `score` で対応表を開き、次を報告する。
   - Claude の採点での条件別正答率と、事前登録と同じ規則での V − C の判定（質問単位の対応ありブートストラップ10000回、seed 0。下限 > 0 で改善、上限 < 0 で悪化、それ以外は判定不能）。S − C、T − S、V − T、更新と時間の20問は傾向の参考。
   - Qwen の採点との一致率、Cohen の κ、不一致の件数と内訳（ID・条件・層だけを公開）。

## 位置づけと限界

- **主判定は Qwen judge のまま。** Claude の採点は、自己採点の偏りを確かめるための副次の結果で、主判定を上書きしない。両者が食い違えば、そのまま並べて報告する。
- 採点者は実験の設計者（V を提案した側）なので、条件名を伏せる。ただし、回答の書き方から条件を推測できる可能性は残る。
- 採点者は1人（1モデル）で、人間の確認ではない。必要なら、不一致の問題だけを人が盲検で確認する（G3 の手順）。
- 公開するのは集計・ID・ハッシュだけで、質問・正解・回答の本文は ignored の `build/eval/memory/longmemeval-u1/claude-judge/` に置く。

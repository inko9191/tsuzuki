# M2：似ていない記憶は渡さない門（事前登録）

状態：test の返事を作る前に固定する。案は 5dfe6bc でコミットし、W を入れることはユーザーが 2026-10-27 に了承した。固定するときは、J2 と入力を作り、dev で τ\* を決め、judge v3 の文面を決めて、計画ファイル `results/eval/memory/m2-plan.json`（データ・コード・文面の sha256、τ\*）と一緒にコミットする。test の返事はそのあとで作る。実行は `scripts/eval/longmemeval_m2.py`。結果を見たあとで条件・判定は変えない。

## 問い

M1（`docs/MEMORY_MISFIRE_M1_RESULTS.md`）と下見（`docs/MEMORY_MISFIRE_M2_PILOT.md`）で分かったこと：

- 記憶を足すと、英語の一般的な質問の 1〜2 割（下見 14.5%）に「記憶に無いので答えられない」と断る。
- 誤発火の大半は害の少ない使い方で、害のある持ち出しはプローブの 4% ほど。
- 断りはすべて、最上位の類似度が低いときに起きていた。似ていない記憶を渡さない門（G）で、τ 0.30 なら断りが 1.6% に減り、正答は 1 問も落ちなかった。ただし τ はそのデータを見て選んだ。

M2 では新しいデータで、τ を先に決めてから確かめる。**「最上位の類似度が τ 未満なら記憶を足さない」は、断りを減らし、正答を落とさないか。**

## 記憶の作り方

M1 と同じ（`scripts/eval/m1/recall.mjs`）。
- 本体は v0.2.0 のコードで、quick（事実なし）の設定。
- 検索は EmbeddingGemma 300m（Q8_0）で、`retrieve` は 2048 トークン、並べ替えなし。現在の日付の決め方も M1 と同じ。
- 最上位の類似度は、発言と、その利用者のすべての窓との余弦類似度のうち最大のもの。

## τ の決め方（test の返事を作る前に固定）

dev の質問（英語 213、日本語 40）の最上位類似度を使う。0.20〜0.50 を 0.01 刻みで調べ、次の 2 つを両方満たす最大の値を τ\* とする。
- 両言語をまとめて、98% 以上の質問が τ 以上。
- 言語別に見ても、それぞれ 95% 以上の質問が τ 以上。

求めた τ\* は計画ファイルに書いてから test を回す。

決まった値：**τ\* = 0.31**（`build/eval/memory/m2/tau.json`）。英語の dev 質問の 98.1%、日本語の 97.5% が 0.31 以上。

## 条件

返事を作るのは M1 と同じ設定：
- Gemma 4 E2B（QAT q4_0、`-c 8192`、思考なし）、温度 0、seed 0、最大 400 トークン。
- システムプロンプトは「You are a helpful assistant.」。記憶の塊は利用者の発言の前に置く（プロキシと同じ）。
- llama-server の並列は下見と同じ 4。

新しく返事を作るもの：
- **N**：記憶なし。
- **P**：今の製品と同じ（v0.2.0 の見出し `recallText`）。
- **W（副・探索）**：P と同じ見出しで、類似度が τ\* 以上の窓だけを入れる。τ\* 以上の窓が 1 つも無ければ記憶なし。作り方は、本体の `retrieve` に、τ\* 未満の窓からしか出てこない発言を除く指定（`inContext`）を渡す。似ている順に詰めるので、残る発言の順は P と同じ。W の塊が P と同じなら P の返事を、空なら N の返事を使う（温度 0 なので新しく作らない）。下見では、τ より上でも別の話題の助言を持ち込む例が日本語で残った。最上位の窓は関係があっても、一緒に入る似ていない窓から持ち込んでいる、という仮説を見る。

既存の返事から組み立てるもの（温度 0 なので、新しく作らない）：
- **G\***：最上位の類似度が τ\* 以上なら P の返事、未満なら N の返事。
- **G\*・F**：G\* の返事が記憶を理由に断っていれば、N の返事に替える。

## 測るもの

- **断り**：返事の中に、記憶・抜粋・渡された情報に無いと言う文がある。判定は `m2_pilot.py` の `REFUSAL`（下見で広げた版、固定）。
- **持ち出しの種類**（judge v3。Qwen3.8 27B、温度 0）：プローブへの返事を 1 件ずつ、次の 3 つのどれかに分ける。
  - **fits**：メモの中身を、発言が求めていることに合う形で使う。関係のある前の話題や好みを使う、発言が前の文脈を前提にしている、前と同じ質問に前の答えを使う、など。
  - **harmful**：発言と関係のないメモの話を持ち込む、質問をメモの話題にすり替える、時期を偽る（「先ほど」など）、メモに無いことを理由に答えを断る・狭める。
  - **none**：メモを使わない。

  judge v3 の文面は下見のデータで作る。使うのは、Claude が分けた 40 件、M1 で Claude が付けた 120 件、下見で断りと判定された P の返事 33 件（harmful として扱う）の計 190 件。文面の sha256 を計画ファイルに書いて固定する。このデータとの一致は合わせ込んだあとの値なので、甘めの参考として報告するだけにする（固定した版 214b6d38 で、harmful 対それ以外の κ 0.88、メモを使ったかどうかの κ 0.87）。judge が答えられなかったもの（打ち切り、読めない出力）は none として数え、件数を報告する。
- **害**：断り、または harmful。
- **正答率**：U2 と同じ、LongMemEval の種類別の judge。日本語も J1 と同じく、英語の基準をそのまま使う。

## 判定のルール（test のみ）

区間はすべて 95%。利用者でまとめた対応ありブートストラップ（10,000 回、seed 0）で出す。

主（両言語をまとめて判定する。両方を満たせば、G\* を製品の既定にする案を出す。既定を変えるかはユーザーが決める）：

1. **断り**：G\* − P の上限 < 0 なら「断りが減る」。
2. **正答率**：G\* − P の下限 ≥ −0.05 なら「正答を落とさない」。

副（報告するが、判定には使わない）：

- 害、harmful、fits（門で失う良い使い方）の G\* − P を、言語別にも出す。
- G\*・F − G\*。F は返事を最後まで受け取ってから送る必要があり、製品のストリーミングとぶつかるので、入れるかは別に決める。
- W − P と W − G\*（害と正答）。
- 記憶を足したプローブと質問の割合。τ を動かしたときの表（記述のみ）。
- 生成の打ち切りの数と、judge の失敗の数。

## 二人目の judge

test の P のプローブへの返事から 150 件を、Claude が条件名と Qwen のラベルを伏せて判定する（none / fits / harmful、断りかどうか）。
- harmful は少ないので、Qwen のラベルで層に分けて取る：harmful か断りから 50 件、fits から 50 件、none から 50 件。足りない分は none から足す。どの層かは Claude には見せない。
- harmful 対それ以外の κ が 0.6 未満なら、harmful と害の結果は「信頼できない」として報告する。主の判定は断りと正答率だけなので、変わらない。
- `REFUSAL` の精度は、test で断りと判定された返事を Claude が全部読んで報告する。

## 予想（結果を見る前）

- τ\* は 0.28〜0.34。
- 断り：英語は P で 10〜16%、G\* で 3% 以下。日本語は P も G\* も 1% 以下（下見では 0%）。
- 正答率：G\* − P は 0〜−2 ポイントで、主の 2 つはどちらも満たす。
- harmful：P で 3〜6%。G\* では、英語は少し減り、日本語はほとんど変わらない。日本語のプローブは履歴と似ていることが多く、門でほとんど止まらないため（下見で 0.30 未満は 4%）。
- fits：G\* で、英語の fits の 1〜2 割を失う。
- W：日本語の harmful が 3 分の 1 ほど減る。正答率は 0〜−5 ポイント（数え上げの問で、似ていない証拠の窓を落とす）。

## 限界

- 本物の会話ではない。英語は LongMemEval、日本語は Claude と E2B が書いたもの。プローブは会話の最初の一言で、続いている会話の途中の発言ではない。
- quick（事実なし）だけ。full では事実も思い出すので、門の類似度を事実でも確かめる必要がある。
- 返事を作るのは E2B だけ。τ\* は EmbeddingGemma 300m での値で、ほかの検索モデルにはそのまま使えない。
- 日本語の test は 40 人（質問 40 問）なので、言語別の正答率の区間は広い。
- judge v3 は下見のデータで作る。そのため、M2 の新しい返事で二人目の judge を使って確かめる。

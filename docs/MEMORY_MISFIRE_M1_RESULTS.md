# M1 の結果：記憶が要らない発言での誤発火

計画は `docs/MEMORY_MISFIRE_M1_PREREG.md`（事前登録、`results/eval/memory/m1-plan.json`）。数字は `results/eval/memory/m1-report.json`、二人目の judge のラベルは `results/eval/memory/m1-claude-labels.json`。事前登録にない確認は `results/eval/memory/m1-exploratory.json`（`scripts/eval/m1/exploratory.py`）で、判定には使っていない。

## 結論（事前登録のルールどおり）

1. **記憶を足すと誤発火が増える：成立。** 誤発火率は N 0.0% → P 9.8%（差 +9.8 ポイント、95% 区間 +7.2〜+12.3）。
2. **見出し H：採用しない。** 誤発火は減った（P 9.8% → H 5.5%、差 −4.3、区間 −6.6〜−2.0）。正答率の差は −4.7（区間 −12.5〜+1.6）で、下限が −10 を下回ったため「正答を落とさない」と言えない。
3. **門 G：採用しない。** Qwen の判定では両方のルールを満たした（誤発火 −2.3、区間 −3.5〜−1.2。正答率 −3.1、区間 −7.8〜0.0）。しかし二人目の judge との κ が 0.41 で 0.6 に届かず、事前登録により 2 と 3 による採用はしない。

製品の既定（`recallText` の見出し）は変えない。

## 数字（test：64 人、プローブ 512 件、質問 64 問）

| 条件 | 誤発火率（プローブ） | 正答率（質問） |
| --- | --- | --- |
| N：記憶なし | 0.0%（0/512） | 6.3%（4/64） |
| P：今の見出し | 9.8%（50/512） | 60.9%（39/64） |
| H：変えた見出し | 5.5%（28/512） | 56.3%（36/64） |
| G：似ていれば P、なければ N | 7.4%（38/512） | 57.8%（37/64） |

言語別（判定には使わない）：英語の誤発火は P 8.2%、H 5.1%、G 3.5%。日本語は P 11.3%、H 5.9%、G 11.3%。

門 G：τ = 0.385（dev の質問の 90% 以上を残す最大の値）。test では質問の 90.6% に記憶を足し、プローブにも 54.5% で足した。最上位の類似度で質問とプローブを見分ける AUROC は 0.66 で、見分けは弱い。

judge の失敗は 0 件。最大 400 トークンで打ち切られた返事は test で N 468、P 378、H 351 件（各 576 件中）。

## 二人目の judge

Claude が 120 件（N、P、H 各 40 件）を、条件名と見出しを隠し、Qwen のラベルを見る前に判定した。N はメモが「none」なので見分けられる。メモは、ユーザーの発言は全文、アシスタントの発言は 300 文字までで読んだ。

- 一致率 86.7%、κ = 0.41（< 0.6）。
- 食い違った 16 件は、**すべて Claude が「持ち出した」、Qwen が「持ち出していない」**。Qwen が誤発火を見逃す向きにずれている。
- Claude の誤発火率は N 0/40、P 14/40（35%）、H 9/40（22.5%）。条件ごとに別のプローブを引いているので、この差は対になっていない。
- 見逃しの例：「以前の会話でも触れられていましたが、…チワワや…」（明らかな誤発火）、メモにある NYC と中国の花瓶から NYC のオークションハウスを勧めた、発酵食品一般の質問をメモの話題のパンに絞った。

つまり Qwen の数字は、問題の大きさを小さめに見積もっている可能性が高い。

## 事前登録にない確認（判定には使わない）

**日本語のプローブの重複。** 日本語の test のプローブ 256 件のうち 35 件（13.7%）は、同じ利用者の履歴にある発言と一字一句同じだった。J1 は利用者をまたいで同じ最初の一言を使っており、入力を作るときにセッションの ID でしか除いていなかった。このときモデルは前の答えをほぼそのまま繰り返し、Claude は「持ち出した」、Qwen は「持ち出していない」とした（8 件中 5 件が食い違い）。35 件を除いても結論は同じ：P − N +10.1（区間 +7.5〜+12.8）、H − P −4.2（−6.8〜−1.7）、G − P −2.5（−3.8〜−1.3）。除いたときの κ は 0.52 で、まだ 0.6 に届かない。

**記憶を理由に答えない返事。** 英語のプローブで、「I do not have any information in my memory about the purpose of a peacock's feathers.」のように、一般的な質問に記憶にないから答えられないと返したものが P で 32/256 件（12.5%）、H で 28/256 件（10.9%）、N で 0 件。誤発火の定義（メモの中身を使う・覚えていると言う）には当たらないので、Claude は 0 とし、Qwen も 3 件しか誤発火にしていない。誤発火とは別の、記憶を足すことの害として数えるべきもの。日本語ではほぼ出ない（H で 1 件）。

**H が落とした質問。** P が正解で H が不正解は 4 問、逆は 1 問。4 問のうち 1 問は「ワークショップの日付が記憶にない」と答えなかった（慎重になりすぎた）。2 問は日付の前後と足し算の取り違え。1 問は好みに沿った提案かどうかの判定の揺れ。64 問では、見出しのせいか揺れかを分けられない。

## 限界

- 本物の会話ではない。プローブは別の会話の最初の一言。日本語のプローブの 13.7% は利用者自身の過去の発言と同じだった（上）。
- 答えたのは E2B だけ。返事の多くが 400 トークンで打ち切られている（後半の「前にも話したように」は見えていない）。
- 記憶が要る質問は 64 問で、正答率の区間は ±10 ポイントほどある。
- 誤発火の judge（Qwen）が見逃す向きにずれていて、二人目との κ が足りない。

## 次にやるなら（別の事前登録として）

1. 誤発火の judge を直す。前の答えの繰り返しや、話題をメモに寄せることも数えるよう文面を変え、test を見る前に新しい目隠しの組で κ ≥ 0.6 を確かめる。
2. 見出しで「答えないこと」も防ぐ。例：「役に立たなければ、無いものとして自分の知識で答える」。
3. 質問を増やして正答率の区間を狭める（LongMemEval-S の 500 問など）。
4. 日本語のプローブは、利用者の履歴と同じ文面を除く。

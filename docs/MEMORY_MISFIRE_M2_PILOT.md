# M2 の下見：誤発火と「記憶を理由に断る」をどう直すか（探索）

M1（`docs/MEMORY_MISFIRE_M1_RESULTS.md`）の後に、直し方の仮説を立てて、M1 のデータで試す。M1 の test は結果を見たので、ここでの数字は**探索**で、採用の判定には使わない。効いたものだけを、新しいデータの M2（事前登録）で確かめる。仮説と予想は結果を見る前にここに書いて固定する。実行は `scripts/eval/m2_pilot.py`。

## 何が起きているか（M1 から）

- 要らない発言に記憶を足すと、過去を持ち出す（誤発火）。Qwen の判定で P 9.8%、Claude の判定で 40 件中 35%。
- 英語では、一般的な質問を「記憶にないので答えられない」と断る（P 12.5%、記憶なし 0%）。見出し H（「関係なければ使わず、触れない」）でも 10.9% で、ほとんど減らない。
- 誤発火の例には「以前の会話でも触れられていましたが」「Based on the information you provided」のように、記憶を**利用者が今渡した資料**として扱うものが多い。

## 仮説

1. **置き場所（S）**：今は記憶の塊を利用者の発言の中、メッセージの直前に入れている（`user_message`）。小さいモデルはこれを「利用者が今渡した資料」と読み、使おうとする。資料に答えが無いと「資料に無い」と断る（検索つき回答の癖）。記憶をシステムプロンプトに移すと、どちらも減る。
2. **指示の中身（H2）**：今の見出しは、記憶が何かは言うが、関係ないときどうするかを言わない。H は「使うな・触れるな」を足して誤発火を減らしたが、「それ以外は自分の知識で答えてよい」を言っていないので断りが減らなかった。この一文を足すと断りが減る。
3. **渡す量（R）**：小さいモデルは、渡された無関係な文章を無視するのが苦手で、指示だけでは限界がある。関係ないものは最初から渡さない方が確実。ただし類似度では見分けられない（M1 の AUROC 0.66）。E2B 自身に「この発言に答えるのに、この記憶は要るか」を先に一言で聞いて決めれば、類似度より見分けられる。
4. **安全網（F）**：断りは文面で機械的に見つけられる。見つけたら記憶なしで答え直せば、断りはほぼ無くなる。費用は該当したときの 1 回分だけ。

## 試すもの（M1 の test：64 人、プローブ 512、質問 64）

生成するもの（Gemma 4 E2B、M1 と同じ設定。ただし速さのため llama-server の並列を 4 にする）：

- **S**：今の見出し（P）のまま、記憶の塊をシステムプロンプトの後ろに置き、利用者の発言はメッセージだけにする。
- **H2**：置き場所は今のまま。見出しは H に次の一文を足す：「Answer everything else from your own knowledge as usual; never say you cannot answer because something is not in these excerpts.」
- **SH2**：H2 の見出しで、システムプロンプトに置く。

既存の返事から組み立てるもの（新しく生成しない。温度 0 なので同じ入力なら同じ返事）：

- **R1・P**：E2B に発言だけを見せて「前の会話の情報が要るか」を yes/no で聞く。yes なら P、no なら N の返事。
- **R2・P**：E2B に発言と記憶の抜粋を見せて「良い答えにこの抜粋が要るか」を聞く。yes なら P、no なら N。R2 は SH2 にも組み合わせる（R2・SH2）。
- **F・P、F・SH2**：返事が記憶を理由に断っていれば、N の返事に替える。
- 比較用に M1 の N、P、H、G も同じ物差しで測り直す。

## 物差し

- **誤発火（judge v2）**：M1 の Qwen は見逃しが多かった（食い違い 16 件すべてが見逃し）。そこで文面を直す。メモにあってメッセージに無い細部を使う、メモの答えを繰り返す、話をメモの話題に寄せる、覚えていると言う、のどれかなら yes。記憶に無いと言うだけの断りは no（断りは別に数える）。M1 で Claude が付けた 120 件のラベルとの κ を先に測る。この 120 件は文面を直すときに見ているので、ここでの κ は甘めになる。M2 では新しい目隠しの組で測り直す。
- **断り**：返事の中に、記憶・抜粋・渡された情報に無い、と言う文があるか（英語と日本語の決まった言い回しで探す。`m2_pilot.py` の `REFUSAL`）。
- **正答率**：M1 と同じ LongMemEval の judge。
- 差は P との差で、利用者でまとめた対応ありブートストラップ（10,000 回、seed 0）。日本語の重複プローブ（35 件）を除いた値も出す。

## 予想（結果を見る前）

judge v2 の誤発火は M1 の数字より高く出るはずなので、P との相対で書く。

| 試すもの | 誤発火（P 比） | 断り（英語、P は 12.5%） | 正答（P との差） |
| --- | --- | --- | --- |
| S | 約 3 割減 | 5% 前後 | ±3 ポイント以内 |
| H2 | H と同じくらい（4〜5 割減） | 3% 以下 | H と同じくらい（0〜−5） |
| SH2 | 5〜6 割減 | 2% 前後 | 0〜−5 |
| F・P | P とほぼ同じ | ほぼ 0 | P と同じ |
| R1・P | 8 割減 | 0 に近い | −10 前後（好みに合わせる質問を落とす） |
| R2・P | 6 割減 | 減る | −3 前後 |

一番の候補は SH2 + F で、R2 を足すかは正答の落ち方しだいと予想する。どれでも 0 にはならないと思う。残る誤発火の一部は、利用者が前に言った好みに合わせる（ポッドキャストの好みなど）ような、害の少ない使い方だから。残った yes から 40 件を Claude が読み、「関係のある個人化」と「無関係・こじつけ・覚えているふり」に分けて数える。

## 限界

- M1 の test を使い回すので、文面の調整は M1 の結果に合わせてしまう恐れがある。数字は M2 で新しいデータを使って確かめるまで主張しない。
- 並列 4 で生成するため、M1 の返事（並列 1）とは数値の細かい揺れがありうる。
- 返事は M1 と同じく最大 400 トークン。

## 結果（探索。2026-10-27、`results/eval/memory/m2p-report.json`）

judge v2 は、M1 で Claude が付けた 120 件との κ が 0.79（M1 の Qwen は 0.41）。食い違い 7 件はすべて judge v2 の見逃しで、多くは判断が分かれるもの（同じ質問の繰り返しなど）。文面を直すときにこの 120 件を見ているので、甘めの値。

仮説ごとに：

1. **置き場所（S）：半分だけ当たり。** 誤発火も断りも減ったが、正答も落ちた。落とした質問は「姉の Emily はどこに住んでる？」に「個人情報は分からない」と答えるなど、記憶を使わなくなっただけだった。システム側に置くと、関係のある記憶も関係のない記憶も同じように軽く扱われる。
2. **指示を足す（H2）：外れ。** 断りはほとんど減らず（−0.8）、正答だけが落ちた。S と組み合わせると、S だけより断りが多かった。
3. **E2B の門（R）：外れ。** 発言だけを見せる R1 は 576 件すべてに no と答えた。記憶も見せる R2 は、記憶が要る質問の 59% に no と答えた。E2B には「要るかどうか」を判断させられない。
4. **安全網（F）：当たり。** 断りは 0 になり、正答は 1 問だけ減った（P の正答の文中に「記憶に無い」という言い回しがあったため）。誤発火は変わらない。

### 誤発火の中身

judge v2 が P で誤発火とした 116 件から 40 件を Claude が読んで分けた（`results/eval/memory/m2p-severity.json`）。

| 種類 | 件数 |
| --- | --- |
| 前にも同じ（ほぼ同じ）質問をしていて、前の答えを繰り返した（J1 のデータの重なり） | 16 |
| 関係のある前の話題や、利用者が言った好みを正しく使った | 12 |
| 発言そのものが前の文脈を前提にしている（"continue"、"redo"、「前の基準で」） | 3 |
| judge の誤り（メモを使っていない） | 2 |
| **害のあるもの**：無関係な前の話を持ち込む、質問をすり替える、「先ほど」と時期を誤る、前の会話を理由に断る | **7** |

害のあるものは 40 件中 7 件で、プローブ全体に直すと 4% ほど。誤発火の 8 割近くは、害の少ない「覚えている」使い方だった。日本語の 16 件は J1 の作り方の問題で、本物の会話では「前にも聞いたね」という場面に当たる。

### 害は「似ていない記憶」に集中する

- 断り 37 件は、**すべて**最上位の類似度が τ（0.385）未満のときだった。
- 害のある誤発火 7 件のうち 3 件と、文脈を前提にした 3 件は τ 未満だった。「関係のある過去を使った」12 件は 11 件が τ 以上、「同じ質問の繰り返し」16 件はすべて 0.65 以上だった。

### ここまでの結論（探索）

- E2B に「関係ない記憶を無視させる」工夫（見出し、置き場所、自己判断）は、どれも記憶を使う量そのものを減らすだけで、要る質問の正答も同じように落とす。
- 害（断りと無関係な持ち出し）は、似ていない記憶を渡したときに起きる。**似ていない記憶は渡さない（低めのしきい値の門）＋断りの安全網（F）**が一番安く、正答を落とさない候補。計算は増えない（類似度はもう計算している）。
- しきい値より上でも、日本語で別の話題の助言を持ち込むものが残る（7 件中 4 件）。これは小さいモデルの限界で、見出しでは直らなかった。
- 次は M2 で、新しいデータで確かめる。τ は dev で決める（例：dev の質問をすべて残す最大の値）。主な物差しは「断り」と「害のある誤発火」（種類を分ける judge）、正答率の非劣性。

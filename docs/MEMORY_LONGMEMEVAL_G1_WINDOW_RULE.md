## 値を測る前に決める規則

30問全ての元のrerank入力を、保存済みfact/p2/embeddingと凍結検索・候補数・プロンプトからCPUで復元する。候補本文を切り詰めず、候補数を変更しない。QwenのCPU `/apply-template` と `/tokenize` のみ許可し、completion/回答/rerank/judge HTTPは送らない。既存サーバーを起動・停止・変更しない。停止gateは残す。

入力最大値をMとし、出力120・既存余裕128を加えてから**10%余裕**を付ける。必要窓 `ceil(1.10 * (M + 120 + 128))` を満たす **16384,32768,65536の最小**を選ぶ。最大値や分布を見る前の規則であり、結果に応じて10%を変えない。65536でも入らないなら実行せず人間確認を待つ。

回答はC/B8192・A131072を維持。回答の出力256・既存余裕128込みで検査する。8192不足なら窓を勝手に変えず人間確認を待つ。A入力は全30問の元preflightを保持。

## 診断の範囲

30問のrerank全入力、候補ごとの番号・unit ID・返す原発言ID・token数、1候補だけでも8kを超えるか、累積で超えるか、最大/p50/p90/minを報告する。候補番号は凍結dense順位のまま。公開はIDと長さだけ、本文はignored build/evalのみ。

最終C入力の順位は未受信rerankで決まるので、**実際の最終C入力は今は存在しない**。CPUではdense順位の参考C入力と、各候補を先頭にした参考入力、1024+512予算とsystem/question/templateの長さによる保守的見積もりを分ける。これを最終Cの実測と呼ばない。再開後のrerank30出力を固定規則で反映し、回答生成前に実際のC全30入力を厳密に検査する。超過なら停止し人間確認。

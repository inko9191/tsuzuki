## なぜこの実験か（G1 からの仮説）

G1（英語30問、C-final-norw）では、C の不正解15問のうち11問が「根拠セッションは入力にあるのに答えを誤った」側だった（探索的分析 9dd71ed）。内訳は棄権5、古い値4（すべて knowledge-update）。G1 の記録は「新しい標本で確認するまで設計変更の根拠にしない」としている。U1 はその確認である。

コードを読んで、回答入力に次の2つの性質があることを確かめた（内容は見ていない）。
- 取り出した発言は関連度の順に並び、日付の行は各セッションの初出にしか付かない。同じセッションの発言が後で再び出ると、直前の別セッションの日付の下に表示される。
- 質問の日付（question_date）を渡していない（G1 登録にも「相対日時問題に不利な可能性」と記載）。
- 加えて、LongMemEval-S の 500 履歴のうち 211 件で、セッションの並びが日付順ではない（メタデータの日付だけで確認）。「直近1024トークン」は並びの末尾から取るので、日付として最新とは限らない。

## 条件（同じ取り込み・同じ検索・同じ再ランキングを3条件で共有）

- **C-final-norw**：凍結のまま（G1 と同じ関数・プロンプト・予算）。
- **S（日付順に並べるだけ）**：T と同じ本文（日付順の履歴・直近・記憶の表示）を、凍結のシステムプロンプトとテンプレートで渡す。質問の日付と追加の規則はなし。並び順の効果だけを切り分ける。
- **T（時間を意識した入力）**：
  - 履歴をセッションの日付順に並べ替えてから、凍結と同じ規則で直近1024トークンを取る。
  - 記憶512トークンは凍結と同じ順位・同じ打ち切り規則（入らない発言が来たら止める）で選び、表示だけ日付順にする。各セッションのまとまりの先頭に Date 行を付ける。
  - 回答の入力の先頭に `Current date: <question_date>`。
  - システムプロンプトは凍結文の後ろに4文を足す（plan の `system_T`）：日付の読み方、異なる日付で食い違うときは最新が現在（過去を問う質問を除く）、`Later update` 行の意味、経過時間の計算。
- **V（取り込み時の更新リンク）**：T に加えて、
  - 取り込み時、日付順に各セッションの事実（凍結 fact の出力）を、それより前のセッションの事実のうち埋め込みの cos が高いもの（新しい事実ごとに上位2件、合計最大20件）と比べる。Qwen に1セッション1回だけ「どの古い事実が新しい事実で古くなったか」を JSON で答えさせる（plan の `update` プロンプト、temperature 0、seed 0、max_tokens 300、JSON スキーマ）。
  - 古くなった事実 → 最新の置き換え（連鎖をたどる、最大2件）。
  - 回答入力の組み立てでは、凍結の順位で古い発言が来たら、その直後に置き換えの発言を順位に差し込む。古い発言の下に `Later update (<日付>): <新しい事実の文>` を付ける。注記も512トークンの予算に数える。
  - 更新判定の解析失敗・窓超過は「そのセッションのリンクなし」として数え、再生成しない。

回答の生成設定・スキーマ・出力は凍結のまま（am.GENERATION、am.SCHEMA、8192窓）。

## 標本

- 公式 LongMemEval-S cleaned（G1 と同じ revision・SHA256）。
- G1 の30問を除いた470問から、内容を見ずに ID と種類だけで抽出。seed `longmemeval-u1-v1`、`sha256(seed|id)` の昇順。

## 実行

G1 と同じ Qwen（GGUF の SHA256・build を plan に固定）、host cache off、1並列、他の GPU 作業なし。各工程で新しいサーバーを起動する。
fact 取り込み（8192）→ 埋め込み（Qwen 停止中）→ 更新判定（8192）→ 再ランキング（16384、G1 と同じ）→ 回答 C/S/T/V（各8192、各条件で新しいサーバー）→ 採点（8192）。

## 採点と判定（先に固定）

- 採点：G1 と同じ固定 Qwen judge（公式 LongMemEval の種類別プロンプト、`longmemeval-g1-judge.json`、yes/no の厳密解析）。judge には質問・正解・回答だけを渡し、条件名は渡さない。質問と条件の順序はハッシュで匿名化する。
- **主比較：全30問の V − C の正答率差。** 質問単位の対応ありパーセンタイル・ブートストラップ（10000回、seed 0）。
  - 95%区間の下限 > 0 → **改善**
  - 上限 < 0 → **悪化**
  - それ以外 → **判定不能**（「効いた」「効かなかった」とは書かない）
- 副次（傾向の参考、有意性を主張しない）：S − C（並び順）、T − S（質問の日付と規則）、V − T（更新リンク）、更新と時間の20問、層別、棄権率、語彙F1、回答入力に根拠セッションが入った割合（採点後に評価用メタデータで計算）、符号検定。
- 30問は小標本で区間は広い。1問の差は約0.033。結果を見て標本・条件・規則を変えない。

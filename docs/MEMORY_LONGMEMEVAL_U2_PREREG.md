## 背景（探索で見たこと、U1 の30問）

- 記憶の枠 512 → 1024/2048 で正答率が上がり（T 0.53 → 0.70/0.73、V 0.57 → 0.77/0.73）、4096 で下がった（`longmemeval-u1-budget-probe.md`）。
- Qwen の並べ替えを省くと、枠 1024 では下がり、2048 では同等だった（`longmemeval-u1-dense-probe.md`）。並べ替えは1回約16秒。
- 速さの設定（-ub、n-gram の先読み）は効かず、並列は速いが出力が少し変わった（`longmemeval-u1-speed-probe.md`）。
- これらは結果を見た後の選択なので、この U2 で確かめる。

## 実行

- Qwen は G1・U1 と同じ GGUF・build。host cache off。
- **fact の抽出と更新判定は `--parallel 4`**（1スロットの窓は U1 と同じ規則：8192、入らなければ 16384/32768 の最小）。並列は出力を少し変えうる（探索で一致率 78%）が、全条件が同じ取り込みを共有するので条件間の偏りにはならない。逐次との再現性は主張しない。
- 再ランキング（V1024R と C512 用）、回答、採点は1本ずつ。再ランキングの窓は U1 と同じ規則。
- 順番：取り込み → 埋め込み → 更新判定 → 再ランキング → 記憶側4条件の回答 → 記憶側の採点 → **途中報告**（`longmemeval-u2-interim`）→ A の回答 → A の採点 → 最終報告。
- 各要求は1回だけ。止まった場合は受信済みを再利用して再開する。不明な送信中の要求があれば再開しない。

## 判定（先に固定）

採点は U1 と同じ Qwen judge（公式の種類別プロンプト、yes/no の厳密解析）。区間は質問単位の対応ありパーセンタイル・ブートストラップ（10000回、seed 0）。

1. **主比較①：P − C512（全40問）**：下限 > 0 → 改善、上限 < 0 → 悪化、それ以外 → 判定不能。
2. **主比較②：P − A（A の窓に入る問）**：下限 > 0 → **上回る**。それ以外で下限 ≥ −0.03 → **同等以上（非劣性）**。上限 < 0 → **下回る**。それ以外 → **判定不能**。全40問（A の窓超過を0点）の運用比較は別に示す。
- 副次（傾向の参考）：V1024R − C512、P − T2048（更新リンク）、P − V1024R（並べ替えなし2048 対 並べ替えあり1024）、層別、棄権率、根拠セッション被覆、1問あたりの回答時間（A 対 P）。
- 副次の採点者：U1 と同じく、Claude が条件名を伏せたシートで採点し、Qwen の採点を開く前に保存する（手順は `MEMORY_LONGMEMEVAL_U1_SECONDARY_JUDGE.md` と同じ、5条件版）。

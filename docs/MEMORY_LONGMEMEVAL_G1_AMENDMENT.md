## 3区分と報告

主95%区間は元登録の履歴cluster paired percentile bootstrap10000回seed0。判定をこの順序で行う：

1. **成立**: C−Aの主95%区間下限 >= −0.03。
2. **不成立**: 1を満たさず、主95%区間上限 < 0。
3. **判定不能**: それ以外。

人間が列挙した1/2は例えば[-.02,-.01]で重なるため、成立条件を優先する。この例は許容幅内の成立であり、Aより小さい負差を隠さず示す。補助の層別bootstrapも同じ規則で別判定を示すが、元登録の「両区間が成立すること」を主判定の追加条件にしない。許容差±.03内の同等性は別に区間全体で判定。

判定不能では「再現した」「再現しなかった」と書かない。点推定の符号・大きさ・両区間・タイプ別件数と傾向を示す。不成立と不確実を混ぜない。成立も登録英語標本/固定自己judgeの範囲に限定し、汎用的な一般化や高い絶対正答率とは呼ばない。

## Aの窓超過は別枠

全30質問を残し、全てのA入力を回答生成前にQwen tokenizerで検査する。`input+256+128<=131072`ならA-eligible、それ以外はA-window-overflow。抽出の差替え、全文切断、256k、再生成をしない。eligible一覧/hashは元データと入力長だけから生成前保存する。

- **意味的な主比較**: A-eligibleの全対応質問でC−A。C/A/Bの生成・judge失敗は0点で保持し、成功した回答だけには絞らない。eligible数と各層件数を明記。eligibleが0なら主比較は算出不能、判定不能。補助層別区間は残る層だけ、欠けた層を復元しない。
- **全30の運用比較**: A-window-overflowをAの0点失敗として保持、C/Bは全30を評価。件数・種類・入力token長と点差/区間を別表へ。この比較だけの改善を、Aが読める履歴での意味的な優位性とは呼ばない。
- overflow問のAはHTTP0回・failure_kind=input_overflowとしてjournalへ記録。A全30の登録記録は揃える。A-window-overflow問も人間レビュー一覧へ残すが、A回答の欄を窓超過として表示する。

fact/C/B/rerank/judgeの窓超過は元登録どおり停止し確認待ち。Aの窓超過だけはこの事前規則で別枠に残して続行する。

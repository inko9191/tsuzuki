# E1：小さいモデル（Gemma 4 E2B）でも記憶で戦えるか（事前登録）

状態：実行前に固定。計画 `results/eval/memory/longmemeval-e1-plan.json`（問題、モデルのハッシュ、E2B の窓、コードのハッシュ）をコミットしてから回す。結果を見たあとで条件・判定は変えない。

## 問い

普通の PC で長期記憶を使うなら、小さいモデルで動くことが前提になる。U2 では Qwen3.8 27B で、記憶（P、2048 トークン）が全文（AT、同じ書式）を上回った。**答える役を小さいモデル Gemma 4 E2B に替えても、記憶があれば、大きいモデルに全文を読ませた場合に並べるか。**

## 条件

- **E2B-P**：U2 で Qwen の P が受け取ったのと**まったく同じメッセージ**（`build/eval/memory/longmemeval-u2/run/memory-inputs.json` の P。記憶は Qwen のパイプラインで作ったもの、日付つきの書式も同じ）。替えるのは答える役だけ。
- **E2B-AT**：U2-AT と同じ書式で全文を渡す。E2B の窓に入る問だけ（入らない問は「窓に入らず」として 0 点）。
- 参考（既存の結果、再計算しない）：Qwen-P（U2）、Qwen-AT（U2-AT）。

## 実行

- モデル：`gemma-4-E2B_q4_0-it.gguf`（Google 公式の QAT q4_0、`huggingface.co/google/gemma-4-E2B-it-qat-q4_0-gguf`、Apache-2.0、SHA256 を確認済み）。
- サーバー：U1/U2 で登録した llama-server の引数（`--reasoning off`、1 スロット、`LLAMA_ARG_CACHE_RAM=0`）で、モデルのファイルだけを替える。窓は GGUF の `context_length`。
- 回答：U2 と同じ（1 問ずつ、`am.GENERATION`、JSON スキーマ）。入力のトークン数は E2B 自身のチャットテンプレートとトークナイザで数える。
- 採点：U2 と同じ Qwen judge（Qwen3.8 27B、8192）。副次の採点者として、Claude が E2B-P と E2B-AT の回答を、条件名を伏せたシートで、Qwen の採点を開く前に採点する（U2 と同じ流儀）。

## 判定

区間は質問単位の対応ありパーセンタイル・ブートストラップ（10000 回、seed 0、U2 と同じ関数）。「同等」の幅は U2 と同じ −0.03。

- **主：E2B-P − Qwen-AT（40 問）**。下限 > 0 → 上回る。下限 ≥ −0.03 → 同等以上。上限 < 0 → 下回る。それ以外 → 判定不能。
  - 意味：「小さいモデル＋記憶」が「大きいモデル＋全文」に並ぶか。
- 副：
  - E2B-P − E2B-AT（E2B-AT が窓に入った問、同じ規則）：小さいモデル自身でも記憶が全文に勝つか。
  - E2B-P − Qwen-P（傾向）：答える役を小さくした分の損。
  - **製品の目安**：E2B-P の正答率 ≥ 0.50。
  - 種類別、棄権率、回答時間。

## 限界

- 記憶は Qwen 27B が作ったもの（事実の抜き出しと更新リンク）。E2B に記憶づくりまで任せた「全部小さいモデル」の構成は、この実験では測らない（次の段階）。
- 英語の LongMemEval のみ。日本語は別に確かめる。
- 40 問なので、大きな差しか見えない。

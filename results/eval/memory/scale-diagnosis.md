## 読み方（2026-10-24、探索。事前登録した判定ではない）

- **答えは消えていない、押し下げられているだけ。** 5,000 セッションでも答えの発言は上位 200 に 0.867、上位 500 に 0.950 入る。予算 2,048 に入るのは約 8.5 発言なので、端からこぼれている。
- **予算を広げると大きく戻る。** 5,000 で 8,192 にすると 0.517 → 0.783（+0.267 [+0.150, +0.383]、16/0）。ただし入力が 4 倍になり、雑音も増える。小さいモデルの回答が良くなるかは測っていない。
- **並べ直しの上限も同じくらい。** 候補 30 窓の中に答えがある割合は 0.783。候補を上位 200 発言まで広げれば上限は 0.867。実際のモデルによる並べ直しは上限より下になる。
- **日付で絞ると規模の影響がほぼ消える（上限）。** ±7 日なら 500〜5,000 で 0.78〜0.82 とほぼ一定。正しい範囲を知っている前提の上限で、質問から範囲を取り出せる場合（「先週」「昨日」など）にしか使えない。
- **BM25 の融合は効かない。** 5,000 で +0.067 [−0.050, +0.183]。knowledge-update は上がるが（0.50 → 0.90）、preference が下がる（0.30 → 0.10）。

次の候補（GPU が空いてから、回答まで測る）: 5,000 セッションで E2B が答える条件として、現状 2,048 / 予算 8,192 / 上位 200 発言を E2B で並べ直して 2,048 / 日付の言葉がある質問だけ日付で絞る。

限界: 取り出し段階の指標（回答の正誤ではない）。英語の LongMemEval、窓だけ（事実なし）、時系列は人工（1 日 15 セッション）、日付の絞り込みは正しい範囲を与えた上限。

副産物: Memory を作っては閉じると、質問を埋め込んだ Memory が解放されない（`AbortSignal.any` が閉じた後も到達可能）。長く動かす 1 つの Memory でも、質問 1 回あたり約 2 KB が残る（Node v22.23.1、1 万回で約 18 MB）。診断はこれを避けるため Memory を規模ごとに 1 つにした。
